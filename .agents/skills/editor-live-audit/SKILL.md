# Editor live audit

Use this workflow for real multicodex editor checks across the local machine and approved SSH hosts.

1. Inspect repository state, memory pressure, installed build metadata, and active multicodex processes. Record and preserve all pre-existing processes and resources.
2. Build the exact clean repository commit. Detect each host's operating system and architecture, build once per distinct target, and never copy a client binary to a different target. Resolve each installed command through symbolic links and inspect the real executable and its parent directory; a Linux symlink's displayed `0777` mode does not describe its target's permissions. When the real executable and parent are current-user-owned and writable, stage the matching binary beside the target, verify it, set mode `0755`, and atomically rename it over the target while preserving the system link. Stop for authority when the real target is not safely writable; do not overwrite it through the link or infer permission from the link mode. Replace binaries without stopping active editors, monitors, host processes, or terminal sessions, and verify file format plus `go version -m` revision and modified state. Restart only an isolated audit editor after all replacements finish.
3. Use a new temporary `MULTICODEX_HOME`. Run the editor with `TMUX` unset. Never use the user's configured editor state for destructive tests.
4. Use only the multicodex repository for Git workspace tests. Use explicit private scratch directories for non-Git remote tests. Never modify another repository.
5. Exercise the real TUI with mouse and keyboard: add hosts and projects; click a project and verify its one project terminal opens in the exact original directory without changing Git worktrees; reopen it and verify the same session returns; use `Ctrl+N` on the project to require a workspace name and create the automatic first workspace terminal; run host markers, paste ordinary text, add and rename workspace terminals, use dynamic slots, and switch hosts. Keep one unselected window changing and another quiet; verify `●` and `·` update without opening either window, the sidebar title continues its live pulse, and stopped and offline windows show `×` and `?`. Verify the visible MacBook controls without Home, Page Up, Page Down, or function keys: arrows, Option-arrow paging, Command-arrow edges, Help, create, rename, cancel, and their shown fallbacks. Upload one synthetic attachment, verify its digest and unsubmitted terminal draft, and clear the draft. For Git, verify the exact worktree lock, switch to a second branch, reconnect, and confirm deletion preserves that second branch. Test adoption through the backend integration path with an exact temporary tmux socket and synthetic session: verify eligibility, stable session and pane identifiers, exact markers, preserved cleanup, release, and unchanged process state. Never adopt a user's session during an audit. When the user explicitly authorizes real Codex calls, run one harmless read-only `multicodex exec` prompt inside a terminal on each host. Capture output in private scratch files, verify only the exit status and an exact synthetic reply, and do not display routing or account diagnostics. Preserve profile-local Codex state.
6. Saturate tmux history and verify the pane retains at least the documented minimum effective history. Do not treat the configured `history-limit` alone as proof. Enter and leave scrollback, terminate only an isolated attachment transport, and restart only the isolated outer editor. Verify the selected session, marker, pane process, history, and ownership state are unchanged after each recovery.
7. Exercise deletion and cleanup through the editor. Verify confirmation text, altered-resource preservation, cascade deletion, reconnect-selection cleanup, explicit Git branch and worktree deletion, attachments, tmux sessions, control sockets, and host processes. Prove that automatic cleanup reports a stale Git workspace without removing its worktree or branch.
8. Compare exact owned resources before and after the audit. Remove only validated temporary resources and empty isolated registries with the test instance identity or exact scratch prefix. Stop when ownership is uncertain.
9. Run focused tests, repository-required gates, public outgoing-change checks, installation verification, and remote CI for the exact pushed commit.

Keep captured output free of credentials and private account data. Report any pre-existing process that ended naturally; never replace it merely to test a new build.
